案件管理业务流程与前后置条件

代码核对版 · 基于 backend/src/case/* 实际实现（NestJS + TypeORM）· 与上层需求文档口径存在差异，差异处已标注。

核心结论：案件是「四维状态机」。 需求文档通常把它们混为一个「案件状态」，但代码里同一张 cases 表用四个独立字段描述案件的不同侧面：
状态维度枚举值（代码）含义
status
办案节点		 pending_assign → processing → filing → evidence → hearing → appeal → pending_close → closed
异常岔路：terminated（解约）、voided（作废）		 沿真实诉讼/办案节点的细粒度进度。注意 filing/evidence/hearing/appeal 在需求文档未明确，预警模块正是基于这些状态扫描在办案件。
stage
生命周期		 intake → processing → closing → closed 粗粒度生命周期。审批通过（若当前为 intake）自动转 processing；结案报告置 closing；归档置 closed。
change_status
变更态		 normal → changed / terminated / voided 变更/解约/作废标记，独立于 status，用于区分「实质终态」与「仅记录变更」。
approval_status
审批/利冲		 pending / approved / rejected / conflict_hold 案件审批流（提交→通过/驳回）与利冲检索结果（命中冲突则 conflict_hold）。

三、子模块规则要点

利冲检索（conflict-check）

  • 判定 当事人姓名与对方当事人姓名同时命中同一已有案件 ⇒ conflict，案件置 conflict_hold。
  • 仅一方（当事人或对方）命中 ⇒ warning。
  • 都不命中 ⇒ clear。
  • 深度检索 deepCheck 用 LIKE 模糊匹配，并模拟工商数据关联企业；结果落库 approval_status=pending，需主管审批。审批驳回会回写案件 approval_status=rejected。
  • 检索记录落表 conflict_checks，便于追溯。

办案任务 / SOP（case-task）

  • 案件创建时按所选模板（民事/交通/劳动/债务）批量生成任务，初始 PENDING。
  • 任务状态机：pending → in_progress → completed → verified；超期 overdue；可 cancelled。
  • 指派（assign）：pending → in_progress。
  • 进度到 100% 自动 completed；父任务在所有子任务完成后自动置 COMPLETED 并算平均进度。
  • 定时任务 checkAndUpdateOverdueTasks 将超期活跃任务置 overdue。

预警（case-warning）

  • 仅扫描 status 为 processing/filing/evidence/hearing/appeal 的在办案件。
  • 四类真实节点：时效届满、开庭、举证期限、上诉期限。
  • 仅当「剩余天数」命中规则 advanceDays 才生成；级别按剩余天数动态升级（≤1天紧急，≤3天警告）。
  • 去重键唯一；每小时定时任务升级超期预警并通知主办律师。
  • 另含 checkOverdue：扫描 processing 且 deadline<now ⇒ is_overdue=true。

风险评级（analyzeRisk）

  • 案件创建时自动评级，规则触发即加分：
  • 涉案金额 > 50万 ⇒ 1 因子
  • 临近关键期限（开庭/举证/上诉）<15天 ⇒ 1 因子
  • 案由为刑事/行政 ⇒ 1 因子
  • 因子≥2 ⇒ high；=1 ⇒ medium；否则 low。结果写入 risk_level / risk_notes。

五、需求文档 vs 代码 关键差异（提示）

事项需求文档口径代码实际影响
案件状态单一「案件状态」四维：status / stage / change_status / approval_status重要
办案节点未明确filing/evidence/hearing/appeal/pending_close 等明确节点重要（预警依赖）
利冲命中处理未写命中冲突 → conflict_hold，且深度检索需主管审批重要
结案前置可能要求结清/完成代码未强制校验未收款，仅联动应收判断合同结清需注意风控
归档前置需先结案代码未强制，归档与结案是两个独立动作（stage 维度）需注意
自动建档联动未写创建即联动 SOP任务、类案、利冲、风险评级重要
